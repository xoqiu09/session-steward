# 首次结构体验候选：独立复核入口

本轮目标：README 主线、自己的首个项目整理流程、新版合成演示及隔离验证。基线是 `93615419e066b46d01fc6cd8d8df788023c4e0f2`。

安装包按用户要求暂缓。复核候选前不要执行发布、安装、服务接管或正式数据导入；本轮也没有恢复 Router、事件直通、Watchdog 的开发。

## 优先检查

1. README、FIRST-USE、DEMO 与 TRYOUT 是否对应真实行为，是否明确源码候选和公开 v0.2.0 的差别；安装后不会自动拥有作者的项目结构资料。
2. `cmd/steward/demo.go` 是否完全绕开普通服务的历史扫描、真实配置、hook 探测、通知、派活和编排初始化。检查 `STEWARD_HOME`、已有路径、符号链接、端口冲突和退出边界。
3. `internal/demodata` 是否只用合成资料并复用 Core；功能只归一个主用途，Agent 回报不形成用户验收。不要让临时演示路径继承父目录的真实 Git 身份。
4. `examples/project-structure/asset-library.json` 是否与素材册的两个登记 ID 对齐；预览不保存、保存不改变业务状态、用户整理不能被 Agent 覆盖。
5. HTTP 服务是否在浏览器打开前就绪，取消后是否收回监听、连接和数据库；错误时是否清楚保留现场而不覆盖原目录。
6. 复核演示脚本已经改为启动一个服务，不再沿用旧的两终端灌数据方式；文档中没有残留旧操作。

## 可以复现的检查

```sh
go test ./...
go test -race ./...
go vet ./...
go build -o bin/steward ./cmd/steward
bin/steward demo
```

开发进程检查使用 Python 3.9+，输出指定一个全新绝对路径：`python3 scripts/check-demo.py --binary bin/steward --output /absolute/path/to/new-check`。它会生成只含合成材料的验证回执，且不改 `HOME`、`CODEX_HOME`。

在演示中按 FIRST-USE 读阅读站，再导入素材册样例、保存并刷新。检查初始 3 个项目、9 项功能、2 份目录；素材册保存后目录为 3 份，任务、功能状态和用户验收不随之变化。所有项目与报告都是合成的。

前端未改源码；可运行 `web/` 下的 `npm ci`、`npm test`、`npm run build` 并确认 `web/dist` 没有意外差异。不要把个人库、token、会话、正式项目目录或私有试用记录提交到仓库。

普通服务 `history_days: 0` 的会话标题刷新属于基线行为；新演示不调用普通服务，不能用该设置代替独立演示的隔离。若复核发现其他问题，按具体路径与复现列出，不自行扩展到后台编排开发。

- 源码问题：位置、影响、最小复现与建议。
- 检查证据：实际命令、候选提交、运行结果；没运行的写未验证。
- 后续仍待：独立新用户的安装、macOS 放行、hook 信任、真实任务和卸载。
- 打包发布：复核意见处理、候选固定、版本与更新日志对齐后，才生成新试用安装包。
