# 新版合成演示

对应尚未打包的新试用版候选。新版把服务启动与示例资料合在一个 `steward demo` 命令里；不需要先启动普通服务或单独灌数据。

## 启动

在候选源码目录构建一次，需要 Go 1.26.5+：

```sh
go build -o bin/steward ./cmd/steward
bin/steward demo
```

前端已经打包在程序里。运行时不需要 Python、curl、Git、tmux、Claude Code 或 Codex。

程序默认创建新的临时目录，自动选择 `127.0.0.1` 上的空闲端口，并带登录凭据打开浏览器。终端显示的地址、数据目录和停止方式不含凭据，所以直接复制地址到其他浏览器会提示先登录。浏览器打不开时，保持此终端运行，按提示在另一终端用这份程序执行 `STEWARD_HOME="演示数据目录" bin/steward open`：它会打印并打开含本次演示凭据的登录链接（不要转发），进入后点顶部“小镇”。不要省略 `STEWARD_HOME`，否则打开的是你的正式服务。

只启动、不打开浏览器：

```sh
bin/steward demo --no-open
```

自选端口与数据目录时，使用**尚不存在的绝对路径**；父目录需已存在：

```sh
bin/steward demo --dir "/absolute/path/to/new-demo" --listen 127.0.0.1:7799
```

已有目录、空目录、符号链接都不会复用或清空。`STEWARD_HOME` 不决定演示目录；演示不读取那份正式服务配置。端口被占用会直接报错，不接管原服务；省略 `--listen` 可自动换空闲端口。

## 会看到什么

| 示例项目 | 初始内容 | 练习 |
| --- | --- | --- |
| 示例-阅读站 | 3 类用途、4 项功能、完整关系；1 项待查看交付 | 概况 → 功能地图 → 当前推进 → 验证依据 |
| 示例-发布清单 | 3 类用途、3 项功能；合成卡点与提问 | 分清卡点、正式提问和下一步 |
| 示例-素材册 | 2 项功能、尚无目录 | 导入 [asset-library.json](../examples/project-structure/asset-library.json)，预览、保存、刷新 |

初始共 3 个项目、9 项功能、2 份目录、3 个工作项。所有验证状态和活动都是合成的；初始用户验收为 0。素材册导入后应有 3 份目录，但功能、任务状态与验收不变。

所有项目都在演示目录的 `projects/` 下，生成的 README 明确写明合成样例。状态与结构通过原有 Core 接口保存，没有另建任务状态机。详细练习见[首次使用](FIRST-USE.zh-CN.md)。

## 隔离范围

这个入口不运行普通 `serve` 的初始化流程，因此不会：

- 导入真实历史会话或刷新真实会话标题；
- 安装 hooks、变更 Claude / Codex 配置、接管正式服务；
- 探测或启动 Agent、tmux、模型、派活或后台编排；
- 发送系统通知、Git 远端核对、多设备同步或第三方消息。

演示仍使用本机面板鉴权和写请求保护。登录凭据只写到本次目录，权限为 `0600`；通过“整理项目”、处理合成提问等操作，只会修改这份演示库。真实 hook 接入与会话恢复解析在演示中被禁用，不会用虚构会话 ID 去查真实 Agent 资料；示例会话也不提供“复制恢复命令”，“新建会话”和派活台只说明演示不接入真实 Agent。

开发者可在已构建程序后复现进程检查（仅检查脚本需要 Python 3.9+）：

```sh
python3 scripts/check-demo.py --binary bin/steward --output /absolute/path/to/new-check
```

输出目录必须全新且父目录已存在。它会检查鉴权、目录保存与人工覆盖保护、双实例、端口冲突、示例会话没有恢复命令、浏览器保持连接时也能及时退出和退出持久化，并用工具陷阱检查演示未调用 Agent 工具；过程只使用合成资料，不修改 `HOME` 或 `CODEX_HOME`。这属于开发验证，不是演示运行的额外依赖。

世界工具栏“结构说明”是 SS 教学样本；房间里的同名入口展示本项目。演示数据不包含维护者的真实项目、工作记录或正式库内容。

## 结束与兼容入口

在启动终端按 Ctrl+C，进程会断开浏览器连接，关闭监听端口和数据库。数据保留，便于检查导入是否保存；不会在退出时自动删除你的演示编辑。再次运行创建全新样例，不自动继续上一次。

`scripts/demo.sh` 和 `scripts/serve-demo.sh` 都转到同一个新入口，只需运行其中一个。可以用 `STEWARD_BIN` 指定当前候选的二进制：

```sh
STEWARD_BIN="/absolute/path/to/steward" sh scripts/demo.sh --no-open
```

不要再按旧说明先运行 `serve`，再把示例灌进一个已有数据目录。自动端口与随机目录可以同时运行多份演示；明确指定的地址或目录冲突时需要你另选新值。

本机隔离检查证明的是合成流程和指定边界。它不代替一位新用户在干净 Mac 上完成 App 下载、系统放行、hook 信任、真实任务和卸载；安装包与那一轮验证在独立复核后进行。
