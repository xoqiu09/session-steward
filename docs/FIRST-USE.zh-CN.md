# 第一次使用：看懂一个项目，再看它推进到哪里

本文对应尚未发布的新试用版候选。公开 v0.2.0 可体验基础小镇，但不包含完整项目目录与新版演示。先确认你使用的是候选源码；本轮先复核，不要求安装候选 App。

目标不是把地图填满。走完以后，你应该能解释一个项目的目标、主要能力怎样配合、眼下在做什么、哪些结论还没验收。

## 先看合成演示

在候选源码目录运行：

```sh
go build -o bin/steward ./cmd/steward
bin/steward demo
```

构建需要 Go 1.26.5+，演示本身不需要 Claude Code、Codex 或其他开发工具。程序会打开一个独立端口的小镇，不安装 hooks、不读真实会话，不需要关闭你原来运行的 SS。所有项目、进度与验证结果都是合成资料。

先点 **示例-阅读站** 的房子进入房间，而不是只点名牌到门前。

1. 在“项目概况”说出它给谁用、做什么。沿关系读一遍：准备资料 → 阅读与查找，内容来源又怎样支持阅读。
2. 在“功能地图”展开“阅读与查找”。这里有两项功能，原登记和状态保留在展开内容里。
3. 在“当前推进”查看等待你处理的合成交付。结构目录与这项工作的状态是两种信息。
4. 在“验证依据”展开一个功能。你会看到合成的 Agent 回报；“你已验收”仍是 0，不能用回报替代用户确认。
5. 在“结构整理依据”核对日期、版本与相对路径。这是说明依据，不是文件执行入口，也不是实时扫描结果。

再看 **示例-发布清单**：它有卡点与一个明确标为合成的提问。是否处理这个演示提问，只影响演示库，不会发布内容、执行命令或联系外部服务；演示里没有“复制恢复命令”，用“已处理”关闭即可。

## 练习整理示例素材册

第三个房间故意保留“尚未整理”。它已经登记了两项合成功能；空目录不等于项目未开发。

1. 进入 **示例-素材册**，先记住当前推进和“你已验收”的数量。
2. 展开“整理项目”，再展开“导入、导出与关系资料”。
3. 选择仓库中的 [asset-library.json](../examples/project-structure/asset-library.json)，或者把文件全文粘贴到“粘贴结构 JSON”，点“载入预览”。
4. 检查预览：目标是按用途保存、找回素材；两类用途是“保存素材”“找回素材”；共归类两项功能。**载入预览还没有保存。**
5. 点“保存目录”。项目概况应出现目标和“保留用途与来源，方便之后查找”的关系；功能地图应有 2 类用途、2 项功能，没有待分类功能。
6. 刷新页面，再进入房间。目录仍应存在，来源变成“用户整理”；当前工作、功能实现/验证和用户验收数量保持原样。

如果你改错了：保存前可关闭整理区，重新打开读取已保存目录。保存后可再次编辑并保存，不需要改源码。Agent 建议不能直接覆盖用户手工整理；过时页面保存时会提示目录已变化，先重新打开并比较。

按 Esc 返回地图。房间内“结构说明”读的是所属项目；世界工具栏的“结构说明”仍明确标为 SS 自身的教学样本，不会替你的项目提供现成目录。

## 换成自己的第一个项目

这一节使用正式 App 与你自己的会话，不在合成演示里安装 hooks。安装步骤见 [README](../README.md#三步装好)。当前公开包仍是 v0.2.0；完整目录体验等待新候选复核与发布。

### 1. 确认采集已接入

按 App 引导安装 hooks；它会先备份并只追加 SS 自己的条目。用 Codex 时，还需在 Codex 自己的客户端确认信任。已有会话可能保留旧上下文，首次体验请新开会话。

在一个允许修改的项目里，给 Agent 一件小任务，例如补一句项目用途说明。你应该在小镇看到项目房子和会话。一次普通任务未必会要求额外权限；没有出现“允许/拒绝”按钮，不代表接入失败。

### 2. 给同一个开发 Agent 整理要求

进入该项目房间，展开“整理项目”，点“给 Agent 的整理说明”。复制生成的内容，发回正在开发这个项目的同一条会话。可以补充：

```text
这次先整理 SS 中这个项目的说明和功能目录。
请依据项目 README、已有规格和现有功能登记，说明目标、受众、范围，
按用户要做的事情分类，并解释主要能力之间的关系。
每项已有功能只归一个主用途；不要按文件夹名猜分类，也不要把临时任务当成产品。
保留整理日期、依据版本和必要的相对路径；资料不足的地方明确待核对。
没有登记功能不等于未开发，不要为凑目录虚构功能或完成状态。
可以通过 SS 结构接口保存 Agent 建议，或交给我导入预览。
只整理说明，不改业务代码，不改变任务、验收、编排或执行开关。
```

SS 不会因为这段要求自动启动新会话、调用模型或扫描全部项目。资料由你当前使用的 Agent 在原有权限内整理。

### 3. 看懂后再保存或调整

Agent 直接回报的目录标为“Agent 建议”；也可以在整理区导入 JSON、预览再保存。手工保存会标为“用户整理”。

先检查三个问题：

- 概况能不能用两三句话说清项目？
- 每个用途是否回答一个自然的问题，功能之间的关系是否有依据？
- 哪些内容尚未登记、没有源码依据，或者只是历史信息，是否明确写出来？

如果还没有功能登记，可以先填概况和用途，不强行凑功能数量。业务范围与功能 ID 的规则见 [CORE-FEATURES.md](CORE-FEATURES.md)，结构格式与回报方式见 [project-structure.md](project-structure.md)。

### 4. 再核对真实工作

结构是“这是什么、怎样配合”；“当前推进”继续读取工作项与简报，“验证依据”继续读取功能回报和你自己的确认。

让 Agent 完成那件小任务并交付，查看实际产物，再决定“已处理”或“退回”。处理整项工作、确认某个功能符合要求、批准工具权限和批准代码合并各自记录，不会互相代替。

## 卡住时先看这里

| 现象 | 下一步 |
| --- | --- |
| 刚打开，小镇是空的 | 正常。确认 hooks 已接入、Codex 已信任，再在自己的项目新开会话；不要把作者的截图当作安装后自带数据。 |
| 有房子，没有功能或目录 | 采集与结构整理是两步。让同一个 Agent 读取已有登记并整理；0 项不表示项目未开发。 |
| 没有“整理项目”入口 | 回到项目所属电脑的本机实时视图；远程只读和历史回放不提供编辑。 |
| 导入后提示功能 ID 不存在 | 样例只能用于演示的素材册。自己的项目需要复用本项目已登记 ID；不要借用其他项目的 ID。 |
| 保存提示目录已经变化 | 关闭整理区并重新打开，比较新目录后再保存，避免覆盖并发修改。 |
| Agent 不能覆盖目录 | 目录已有用户手工整理。保留人工版本，把新建议交给用户比较。 |
| 看见功能通过，但实际还不能用 | 展开候选、来源和验证范围。Agent 回报、真实运行、部署与用户验收分别核对。 |
| 下载后看不到本文的新入口 | 核对版本。公开 v0.2.0 与当前源码候选不同，不要反复重装旧包。 |

需要反馈时记录 SS 提交版本（`steward version` 或已登录的 `/api/version`）、macOS / 芯片、Claude Code 或 Codex 版本，以及停在哪一步。当前支持情况和已观察的客户端版本见[手册](GUIDE.zh-CN.md#支持情况)，不把其他版本当成已验证。

## 什么时候算首次体验走通

你可以从小镇找到自己的项目，沿关系说清主要能力怎样配合，并能分清当前工作、Agent 验证回报与你的验收。截图、维护者自测和自动化检查各自保留，不替代你的实际判断。

演示用 Ctrl+C 结束；正式 App 的退出与卸载见 [README](../README.md#更新与卸载)。试用记录可以按[反馈清单](TRYOUT.zh-CN.md)提交。
