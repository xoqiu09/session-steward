# K1：Studio 本机派活台

状态：待做。“回电脑接着做”按钮等 K2 通过。
分支：`feat/dispatch-desk-local`。

## 目标

在正式的 `steward serve` 里有派活台：在 Mac Studio 本机打开小镇广场的派活台，可以选授权过的项目交代任务、看进度、批准、停止、恢复、交给桌面 App。原型 `steward-native-prototype` 的能力搬进来后，原型不再需要单独运行。

## 范围

- **后端。** 把 `internal/nativecontrol` 的 app-server 驱动、租约/epoch、幂等开始、审批映射、`ss_deliver` 并进正式服务。用户自己的 Codex 环境，按命令行参数关子进程 hooks/插件。
- **数据。** 一次迁移：`managed_sessions` 加运行方式和原生会话号，`tmux_name` 对 app-server 任务不再必填（保持对旧数据的唯一性）；`managed_audit` 加设备列；新增“可派活的项目”。不另建任务状态机，原型的映射逐项迁入；迁不过来的写进回报。
- **执行。** 每件任务按 LaunchManaged 的方式新建分支和工作树；客户端不能指定目录、命令、模型。
- **接口。** 派活路由只给本机（loopback 且无转发标记）用；本批先不开 7790 监听，K3 再开。普通远程照旧被 `remoteBlocked` 拒绝。
- **前端。** `/?view=dispatch` 按设计第 4 节；广场加派活台桌子；派活台发起的房子门口挂牌子。沿用小镇组件和样式。
- **接手。** K2 通过后才加“回电脑接着做”按钮（打开 `codex://threads/<会话号>`）；K2 未通过前按钮不出现，页面写“桌面 App 接手还在核对”。

## 不做

- 不开 7790、不配 8444、不做配对（K3）。
- 不改 8443、hub 推送、其他工具 hooks、用户的 Codex 配置。
- 不做微信、Claude、Hermes。
- 不替换 Studio 上的正式安装；真实验证在合成项目和临时 STEWARD_HOME 下做。

## 验收标准

1. 本机可以在两个不同的授权项目里各派一件任务，同时运行互不干扰；未授权的目录无法派活。
2. 关掉页面任务继续；重新打开看到正确状态，不自动重发。
3. 停止、恢复同一会话、Agent 交付进入待验收，均不自动标“已处理”。
4. 审批：本机“仅允许这一次”和“拒绝”都生效，重复决定 409。
5. 普通远程访问派活路由一律拒绝；`remoteBlocked` 原有测试全部保留。
6. 迁移在旧库（含 tmux 托管会话）上可升级，旧托管会话照常工作。
7. 审计记设备、动作、时间、结果，不含任务文字和命令。
8. K2 通过后：“回电脑接着做”能在桌面 App 打开同一会话。

## 验证

`go test ./...`、`go test -race ./...`；`web/` 下 `npm test`、`npm run build` 并提交 `web/dist`；在 Studio 的合成项目里真实跑一遍 1～4 和 8，写清哪些是真实点验、哪些是合成测试。
