# Session Steward 新结构体验试用清单

这份清单对应下一试用版候选，公开 v0.2.0 不包含完整的新结构体验。本轮先复核源码与合成演示，尚未生成新安装包；安装、系统放行和真实 hook 流程在新包准备后再验证。

我们最想知道：**你能否讲清一个项目，知道它正在做什么，并分清 Agent 回报和自己的验收。** 记录哪一步卡住或看不懂即可，不需要替我们定位代码。

## 开始前

- 合成演示：拿到候选源码，使用 Go 1.26.5+ 构建 `cmd/steward`，运行 `bin/steward demo`。不需要安装 hooks 或连接 Agent。
- 真实接入（新包后再做）：macOS 13+、Claude Code 或 Codex，以及一个允许修改的小项目。记录实际客户端版本，不默认所有版本都已验证。
- 每步分开记录“未做 / 通过 / 卡住”和观察。演示通过、维护者自测、新用户使用、用户验收分别保留。

演示使用新的独立目录；正式资料存在 `~/.steward`。只有真实接入时才需要安装 hooks，改配置前会备份；卸载只处理 SS 条目，并保留安装之后其他工具的修改。更细的步骤见[首次使用](FIRST-USE.zh-CN.md)。

## 任务 1：读懂一个示例房间（约 5 分钟）

1. 启动[合成演示](DEMO.zh-CN.md)，进入“示例-阅读站”。
2. 依次看项目概况、功能地图、当前推进、验证依据。
3. 展开一个用途、一个功能和结构整理依据。不要点击验收来制造完成状态。

记下来：
- 能不能用两三句话解释它解决什么问题、主要能力如何配合？
- 能否区分“Agent 报验证通过”和“你已验收”？

## 任务 2：亲手整理素材册（约 5 分钟）

1. 进入“示例-素材册”，确认已有 2 项功能但目录尚未整理。
2. 按[整理练习](FIRST-USE.zh-CN.md#练习整理示例素材册)导入样例，先载入预览，再保存目录。
3. 应出现 2 类用途、1 条关系，2 项功能各归一类；刷新后仍保留。
4. 比较保存前后的当前工作、功能状态和用户验收数量，应没有因此改变。

记下来：
- “预览”和“保存”是否好区分？用途名称是否帮助你理解，而非增加术语？
- 空目录是否被误解成项目未开发？

## 任务 3：在小镇里找东西（约 5 分钟）

1. 点一个项目的名牌：镜头应该飞到那栋房子和门前的菜地，你还在世界地图里。
2. 点“回到刚才的位置”。
3. 点房子本身，走进项目内部看看，再按 Esc 出来。
4. 刷新一下页面（或者退出 App 再打开），看看房子是不是还在原处。

记下来：
- 名牌和房子点起来的区别，你觉得自然吗？
- 有没有哪次镜头自己飞走了，打断了你正在看的东西？

## 任务 4：自己的第一个真实项目（新安装包后再做，约 15 分钟）

1. 按对应版本的安装步骤打开 App、安装 hooks，并在 Codex 里完成信任。
2. 在允许修改的小项目中新开会话，给 Agent 一个小任务，确认房子和会话出现。
3. 用房间中的“给 Agent 的整理说明”，请同一个开发 Agent 整理自己的项目，保存后阅读。
4. 查看小任务的真实交付，决定“已处理”或“退回”。权限请求只有真实发生时才检查；没有额外请求不算失败。
5. 可选：再开一个会话，确认能分清项目、工作项与会话。

记下来：
- 下载、系统放行、hook 信任有没有卡点？安装提示是否说明会修改什么？
- 你能否解释自己的项目，以及哪些事在等你？
- 有没有必须请作者远程帮忙才能继续的步骤？

## 任务 5：结束与卸载（约 2 分钟，可选）

合成演示在终端按 Ctrl+C 停止，数据保留供核对，不会因此卸载或停止正式 App。真实接入后如果不打算继续用：App 菜单选“卸载 hooks…”，再“退出并停止采集”，最后移除 App。

记下来：
- 卸载后，Claude Code 和 Codex 用起来是不是和装之前一样？

## 最后，三个问题

1. 目录是否帮你理解项目和功能之间的关系？请举一处具体例子。
2. 如果明天还能用，你会继续开着它吗？为什么？
3. 哪一步仍需要别人解释，或让你误判了进展？

## 怎么反馈

把记录发给邀请你的人，或者发到 [Issues](https://github.com/xoqiu09/session-steward/issues)。截图很有帮助，但请先确认里面没有不想公开的项目名或内容。**不要贴登录链接、token、`~/.steward` 下的文件或对话全文。**

附上版本和范围：SS 实际提交（`steward version` 或已登录的 `/api/version`）、App 显示版本、macOS / 芯片、Claude Code 或 Codex 版本，以及哪些步骤尚未做。合成验证、真实运行和用户验收分别写，不把未执行项填成通过。
