# P2：工作项关联 PR，网页上合并后自动更新

- 执行：Codex
- 分支：`feat/github-pr-awareness`，在 P1 合并后从最新 main 开
- 依赖：P1（新信号用 `github` 渠道）

## 目标

用户在 GitHub 网页上合并、关闭 PR，或者 PR 的检查跑完时，SS 一分钟内知道，并且：

- 工作项的合并状态更新，过时的合并提醒自动收起；
- 工作详情和每日十分钟里能看到这个工作项对应的 PR：链接、状态、检查结果；
- PR 被关闭但没合并时，明确写“PR 已关闭，未合并”，不当成完成。

## 背景：现在做到哪一步

- `SyncMerges`（`internal/core/merge_remote.go`）每分钟一次，只查 `needs_merge=1`、有分支、还没合并的工作项。
- 它用 `gh pr list --state merged --head <分支> --base <目标>` 找合并证据，要求 head SHA、base 分支、合并提交都对得上，并且合并提交包含在刚拉取的目标分支里。这条规则必须保留。
- 缺口有三个：
  - 不知道开着的 PR，以及它的检查结果；
  - 不知道 PR 被关闭但没合并；
  - 没有 `needs_merge` 标记、但有分支和 PR 的工作，在网页上合并后不会被发现。

## 范围

1. **关联**：给有分支的工作项找 PR，条件是同一仓库、head 分支名一致，并且 PR 的 head SHA 等于工作项分支当前的 SHA，或者是它的祖先。关联结果存下来：PR 号、URL、状态（open / merged / closed）、head SHA、base、合并提交、检查汇总（通过 / 失败 / 进行中 / 没有检查）、取得时间。
2. **刷新**：对所有“没完成、没放弃、已关联或可能有 PR”的工作项定时刷新。
   - 有待处理的工作时，每仓库每分钟最多一次；没有就不查。
   - 用一次 `gh pr list --json ...` 批量取一个仓库的 PR，不要按工作项逐个查。
   - 全部仓库加起来，每小时请求数不超过设计文档“待决定”第 4 条定下的上限。
3. **合并**：PR 变成 merged 以后，仍然走现有证据规则。证据成立时，由 `ScanMerges` 把工作项标为已合并，并把对应的合并审批标为“已在别处处理”，收起提醒。“已合并”的来源仍然只有核对器这一个。
4. **关闭**：PR 被关闭但没合并时，工作项加一个可见标记“PR 已关闭，未合并”，并且出现在每日十分钟的“要你决定”里，选项是“退回修改”或“放弃”。不自动改工作项状态。
5. **显示**：
   - 工作详情：PR 链接、状态、检查结果、最后核对时间。
   - 每日十分钟：待验收一栏的证据里加上“PR #N 检查通过 / 失败”。检查通过算作可核对的证据，检查失败算作验证失败。
6. **信号**：每次 PR 状态变化都记一条 `github` 渠道的信号，`Ref` 写成 `仓库#PR号@headSHA`。

## 不做

- 不对 GitHub 做任何写操作：不评论、不合并、不改标签。
- 不用 webhook。SS 跑在本地，没有公网入口。
- 不读 PR 的评论和代码内容，只读状态、SHA 和检查汇总。
- 不处理 GitHub 以外的托管平台。

## 设计约束

- 只用用户本机已登录的 `gh`。账号不对、没登录、没装 `gh` 时，显示“无法核对 GitHub”，不报错刷屏，其他功能照常。
- 多个 GitHub 账号或 SSH 别名的情况，沿用 #32 里 `resolvedGithubRepository` 的处理方式。
- 网络请求在状态机锁之外完成，沿用 `SyncMerges` 的做法。
- 测试用假的 `gh`（可注入的命令执行器）和合成仓库，不访问真实 GitHub。

## 验收标准

1. 合成场景“分支 → 开 PR → 检查通过 → 网页合并（squash）”：一次刷新后，工作项标为已合并，合并提醒收起，工作详情显示 PR 和检查结果。
2. 合成场景“PR 被关闭未合并”：工作项不变成已完成；每日十分钟出现“PR 已关闭，未合并”，并带“退回修改 / 放弃”两个选项。
3. 只有分支名对得上、head SHA 对不上时，不关联、不标合并。要有测试。
4. `gh` 不存在、未登录、返回错误、超时：都不影响 Git 扫描和其他功能，界面显示原因。
5. 请求频率有测试：没有待处理工作的仓库不发请求；同一仓库一分钟内不重复请求。
6. `go test ./...`、`go test -race ./...` 通过；前端改动跑 `npm test`、`npm run build`，并提交 `web/dist`。
