# P1：信号带来源和时间，快照给出“最近信号”和“信息缺口”

- 执行：Codex
- 分支：`feat/signal-provenance`，从最新 main 开
- 已决定：摘要里加信号的来源类型和时间（设计文档“已决定”第 2 条）

## 目标

后面所有采集器（会话记录、进程、GitHub）都往同一套结构里写信号。这一期先把结构定下来：每个信号说清楚它从哪来、什么时候发生、什么时候收到、怎么回查。界面上每个会话和工作项都能看到“最近一次信号是什么时候、从哪来”。很久没有信号时，明确写“信息缺口”，不写“卡住”。

## 背景

- `event.Event` 已经有 `OccurredAt`、`ReceivedAt` 和 `Source`（provider、client、host）。但是没有“这条信号经由什么渠道来的”，现在默认全是 hook。
- `events` 表有 `occurred_at` 和 `received_at`；`sessions` 有 `last_activity_at`、`last_progress_at`。
- 每日十分钟里的“很久没回报进展”来自简报的 `stale`，意思是“Agent 一直在动，但没有回报进展”。它和“完全没有信号”是两回事，两个都要保留。

## 范围

1. **事件结构**：`event.Source` 新增 `Channel`，取值 `hook`、`transcript`、`process`、`git`、`github`、`hub`、`model`、`user`。现有的入口一律填 `hook`，Agent 主动调用的 `claim/report/deliver` 也算 `hook`，面板上的操作填 `user`。另加一个可选的 `Ref`，用来回查原始信号，例如 hook 事件 ID 或文件加偏移量。旧数据没有这两个字段时，按 `hook` 处理。
2. **会话最近信号**：`sessions` 新增 `last_signal_at`、`last_signal_channel`。只有发生时间更新的信号才能覆盖，规则和现在的乱序保护一样。
3. **快照**：会话和工作项都带上 `signal: {channel, at}`。工作项取它下面所有会话里最新的那一个。
4. **信息缺口**：前端统一用一个函数判断。工作项在进行中（`in_progress`），最近信号超过阈值（默认 30 分钟，放在配置里）时，显示“X 分钟没有任何信号”。这个缺口只是展示出来，不改变任何状态。
5. **显示**：
   - 工作详情和会话详情：显示“最近信号：5 分钟前 · hook”。
   - 每日十分钟的“卡住了”一栏：新增“没有信号”这一类，和“很久没回报进展”分开写。
   - 小镇：人物名牌的悬停提示加上最近信号。
6. **多设备摘要**：把 `signal` 加进摘要，只加渠道和时间，不加 `Ref`。中心机的合并视图里，其他电脑的工作项也能显示“最近信号”和“信息缺口”。

## 不做

- 不新增任何采集器。这一期只定结构，并把现有的 hook 入口接进来。
- 不根据“没有信号”自动改变状态，也不发通知。
- 不改简报的 `stale` 逻辑。

## 设计约束

- 遵守 AGENTS.md 和设计文档的四条原则。
- 数据库迁移必须兼容已有数据，并且可以重复执行；按 `internal/store/schema.go` 现有的方式写。
- `Ref` 里不能出现对话正文、命令内容或文件路径以外的敏感信息。如果是文件路径，只在本机保存，不进摘要。

## 验收标准

1. 新旧事件混在一起时，`last_signal_*` 只会被更新的信号覆盖。要有乱序到达的测试。
2. 用合成快照测试前端：进行中、40 分钟没有信号的工作项显示“40 分钟没有任何信号”；已完成或待验收的不显示。
3. 每日十分钟里，“没有信号”和“很久没回报进展”同时存在时，各写各的，不合并成一条。
4. 摘要（`trimForHub` 之后）里的 `signal` 只有渠道和时间，没有 `Ref`。要有测试。旧版本设备推来的摘要没有 `signal` 时，中心机照常显示，只是不显示信号时间。
5. `go test ./...`、`go test -race ./...` 通过；`npm test`、`npm run build` 通过，提交 `web/dist`。
