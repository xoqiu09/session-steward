# V1：小镇跟着进展走——有菜熟了，镜头自动带你过去

- 执行：Codex
- 分支：`feat/town-follow-progress`，从最新 main 开
- 依赖：无，可以和 P1 并行。P1 合并后，可以在提示里加上“最近信号”；P2 合并后，可以加上“合并完成”这一类时刻

## 目标

开着小镇（世界地图）的时候，某个项目有了值得看的进展，比如一棵菜熟了（工作交付、等你验收），镜头自动、平稳地飞到那块菜地，旁边冒出一张小卡片，一两下就能收菜或去处理。不想被打扰的时候，它不能抢镜头。

## 背景：现有的基础

`web/src/town/WorldScene.tsx` 里的 `WorldStage` 已经有：

- `flyTo(camera, ms)`：平滑飞到某个镜头位置；
- `lastTouch`：记下用户最后一次拖动或缩放的时间。桌面巡游在用户操作后 30 秒内不动镜头；
- 桌面模式巡游（`tourStops`）：轮流看需要注意的街区；
- 收菜模式：`ripeQueue` 找出熟了的菜，`goHarvest` 一棵一棵飞过去，打开验收卡片，镜头会给右侧的卡片留出位置；
- `harvest.ts`：菜的长势。等你决定是“缺水”，待验收是“熟了”，熟了两天没收会“发蔫”。

这次的新功能尽量复用这些，不另写一套镜头逻辑。

## 什么算“值得带你去看的时刻”

只看页面开着的时候实际发生的**变化**。刚打开页面时已经是这样的，不算新时刻（见下面的“离开期间”）。

| 时刻 | 判断 | 优先级 | 卡片上的字 | 按钮 |
| --- | --- | --- | --- | --- |
| 要你决定 | 新出现的待处理权限请求或提问 | 1（最高） | “博客迁移：Claude 在等你允许一条命令” | 去处理 · 稍后 |
| 菜熟了 | 工作项新进入待验收 | 2 | “博客迁移：BLOG-3 熟了，可以收” | 收这一棵 · 开始收菜（N 棵） · 稍后 |
| 合并完成 | `merge_state` 新变成 merged（P2 合并以后网页上的合并也算） | 3 | “BLOG-3 已合并进 main” | 看看 · 好的 |
| 有进展 | Agent 回报了新进展，或者菜从“种子”长成“发芽” | 4（最低） | 不飞，菜地上冒一下小火花 | 无 |

每个时刻用 `工作项或审批 ID + 时刻类型 + 发生时间` 作为唯一键，同一个时刻只触发一次，刷新快照也不会重复触发。

## 什么时候不飞

下面任意一条成立时，不移动镜头，只把时刻放进“动态”队列（见下一节）：

- 用户 30 秒内拖动、缩放、点击过地图（沿用 `lastTouch`）；
- 详情抽屉开着、在建筑室内、正在收菜、正在回放、使用说明开着；
- 页面不在前台（`document.hidden`）；
- 设置里关掉了“有进展时自动带我过去”；
- 这个时刻属于别的电脑，在这里不能验收（“全部设备”视图里其他设备的工作）。

## “动态”队列

- 不能飞或者同时来了好几个时刻时，地图右上角出现一个小标签：“3 处有新动态”。点开是按优先级排的列表，点一项就飞过去。
- 几秒内连续来了好几个时刻（默认 3 秒窗口），只飞优先级最高的那一个，其余进队列，避免镜头来回乱跳。
- 已经处理掉的（例如在别处验收了），自动从队列里移除。

## 飞过去以后

1. 镜头用现有的 `flyTo` 飞到那个街区，取景让菜地和房子都在画面里，并给卡片留出位置（参考 `goHarvest` 的取景）。
2. 菜地上闪一圈光，同时在旁边弹出卡片。卡片在 HTML 浮层里，不要画进 SVG，这样文字清楚，也能用键盘操作。
3. 卡片上的按钮：
   - “收这一棵”：打开这项工作的验收卡片，等于点了这棵菜。验收仍然要用户在卡片里点“验收通过”，**自动飞过去绝不会自动验收**。
   - “开始收菜（N 棵）”：进入现有的收菜模式，从这一棵开始。
   - “稍后”：卡片收起，时刻留在动态队列里。
4. 地图上出现“回到刚才的位置”按钮，点了飞回飞过来之前的镜头。
5. 普通模式下，镜头停在那里不自己飞走。桌面模式（kiosk）下，20 秒内没人操作就继续巡游。
6. 读屏：卡片出现时，用 `aria-live="polite"` 读出卡片上的那句话。

## 离开期间

页面重新回到前台，或者刚打开时，如果自上次看过以后有菜熟了或有新的待决定，不要直接飞，而是在顶部出现一条：“你离开期间：2 棵菜熟了，1 件要你决定” · “带我去看” · “知道了”。点“带我去看”从优先级最高的开始。“上次看过”的时间只记在这个浏览器里，读写都要包 try/catch。

## 设置

小镇“怎么看”面板里加两项，只记在这个浏览器里：

- 有进展时自动带我过去：开（默认）/ 关；
- 自动带我去的时刻：只看“要你决定”和“菜熟了”（默认）/ 也包括“合并完成”。

## 动画和无障碍

- 系统开了“减少动态效果”（`prefers-reduced-motion`）时：镜头直接跳过去，不飞；不闪光，只显示卡片。
- 飞行时长 900 毫秒左右，用缓入缓出；连续飞的间隔不少于 3 秒。
- 卡片在手机宽度下不能挡住菜地；按钮最小高度 44px。

## 范围

1. 新增一个纯函数模块（例如 `town/moments.ts`）：输入前后两次快照，输出新时刻列表。去重、排优先级、判断属不属于本机，都放在这里，方便测试。
2. `WorldStage` 里接入：判断能不能飞、队列、卡片、“回到刚才的位置”、离开期间提示、设置项。
3. 工作室（kiosk 的室内视图）这一期不做，只做世界地图。

## 不做

- 不自动验收，不自动批准，不自动退回。
- 不发系统通知。通知已经有自己的渠道；这一期只管小镇画面。
- 不改收菜模式本身的流程。

## 验收标准

1. `moments.ts` 的测试：
   - 首次加载不产生时刻；
   - 一个工作项从进行中变成待验收，只产生一次“菜熟了”；
   - 同时出现权限请求和熟菜时，权限请求排第一；
   - 其他电脑的工作不触发飞行，只进入队列；
   - 已经处理掉的时刻，会从队列里移除。
2. 组件测试：
   - 30 秒内操作过地图时不飞，只出现“N 处有新动态”；
   - 详情抽屉开着、收菜中、回放中都不飞；
   - 减少动态效果时直接跳过去；
   - 卡片上的“收这一棵”打开对应工作项，“开始收菜”进入收菜模式并从这一棵开始。
3. 用合成演示数据实际看一遍：让一个工作项交付（用演示脚本或 `steward-hook deliver`），镜头在 1～2 秒内飞到那块菜地，卡片出现；点“收这一棵”能看到验收卡片。录一段屏或截三张图：飞之前、飞之后、卡片打开。
4. `npm test`、`npm run build` 通过，提交 `web/dist`。
