# 任务书怎么用

每份任务书都能单独交给执行 Agent。结构固定：目标、背景、范围、不做、设计约束、验收标准、验证命令、回报格式。

## 交给 Codex 的提示词

```text
请执行 docs/perception/tasks/<任务书文件名>。
先读仓库根目录的 AGENTS.md 和 docs/perception/architecture.zh-CN.md，再读任务书。
从最新 main 开分支，分支名用任务书里给的。
做完开草稿 PR，不要合并，不要发布，不要替换正式安装。
最后按任务书里的“回报格式”回复我。
```

## 回报格式（所有任务通用）

```text
## 结果
一两句话：做完了什么，没做完什么。

## 改动
按模块列出改了什么，每条一句。

## 验证
- 跑了哪些命令，结果如何（通过/失败的数量）。
- 用合成数据实测了什么，看到了什么。
- 没有验证的部分，以及原因。

## 偏离任务书的地方
没有就写“无”。有的话写：哪里不一样，为什么。

## 需要用户决定的事
没有就写“无”。

## PR
链接，是否草稿，检查状态。
```

## 审查清单（审查的人用）

- 验收标准逐条对过，每条写“满足 / 不满足 / 无法验证”。
- 没有越过 AGENTS.md 和设计文档的边界：不读对话正文，不把模型判断写成事实，不替用户验收，不扩大采集范围。
- 新增的信号都带来源和时间。
- 测试只用合成数据；没有提交 token、数据库、对话文本或真实项目内容。
- Go 改动跑了 `go test ./...`，涉及状态机或并发的还跑了 `-race`；前端改动跑了 `npm test`、`npm run build`，并提交了 `web/dist`。
- 多设备：只在本机采集，摘要不夹带不该离开这台电脑的字段。
