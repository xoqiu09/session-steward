# P1：信号来源与信息缺口

实现基于 `main@48078ae18e32204aac34eada5a77ef8772c5c4bf`；任务书及架构见 `docs/perception-plan@6f621c29ff9b4a2c430ec96fd36f6500e90ef7d4` 的 `docs/perception/tasks/P1-signal-provenance.zh-CN.md`。

## 当前行为

- 现有采集事件补 `source.channel=hook`，缺少引用时使用事件 ID；本机事件保留可选 `source.ref`。
- 最新信号按发生时刻比较；等时优先级为 hook、transcript、process。工作项从其关联会话和各段关联有效区间取最新观察，后续任务不刷新先前任务。
- 工作/会话详情显示最近来源和时间，小镇角色提示随显示时钟推进。进行中任务超过 `signal_gap_after_min`（默认30）时只显示信息缺口，不改状态或发通知。“很久没回报进展”仍由原简报规则计算，和“没有信号”分别展示。
- 多设备 `signal` 只有 `channel` 和 `at`，不带本机引用。旧设备缺少 `signal` 时保留未知，不编造时间。
- 模型渠道保留在元数据枚举中，但当前 Ingest 拒绝它进入采集状态机；以后通过 P6 独立解释接口写模型推断。

## 面板来源范围

现有工作项创建、修改、简报编辑、会话绑定/解绑、运行结果、审批决定/关闭/合并批准/合并拒绝使用同一 Core 事务辅助记录 `user_action`。只在受控面板路由、业务对象确有变化且事务成功时记录；审计失败则业务动作也回滚。记录只有受控动作名、对象ID和时间，无请求正文、工具参数或审批内容。

没有会话的操作只留独立审计，不制造会话或借用其他会话。用户审计可以在本机事件中查看，但不会推进 Agent 活动时钟、日历会话数或回放状态。项目显隐、功能确认、托管控制等其他面板动作没有在本期扩展为统一事件；其原有用户记录保持原样。

## 数据库与升级边界

追加 schema v5，补会话最近信号两列，可重复执行；一次性把事件索引时间规范为同一时刻的 UTC 纳秒格式，原事件 JSON 不变。仅用合成临时库验证迁移，没有打开真实数据库。

现有 T0 内置升级仍要求安装包 schema 和本机 schema 一致。v4→v5 的正式内置升级依赖后续 U1；本 PR 不改升级守卫、不替换正式安装。

## 合成页面验证

合成场景保留本机36/全部设备48个演示项目：一个40分钟无信号的进行中工作、一个仍有信号但很久没回报的工作，以及40分钟无信号但已待验收的工作。父任务保留可重复的回环演示服务脚本和完整测试日志。

本轮浏览器工具仍返回 Work 设置禁用，因此没有新增真实浏览器截图，也未把接口200当作渲染或用户验收。组件测试覆盖默认可见详情、两类信息分别显示、同cursor时钟推进的角色提示；实际页面、系统读屏及多设备现场待审查/用户后续验收。
