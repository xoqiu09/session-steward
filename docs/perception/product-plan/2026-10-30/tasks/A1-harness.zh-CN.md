# A1：DeepSeek Harness 研究与最小观察插件

状态：仅研究阶段可先行；原型依赖 A0 冻结契约。
分支建议：`feat/adapter-deepseek-harness`。执行时从最新 main 创建独立 worktree；当前没有创建该分支。
共用约束：[索引与回报格式](README.zh-CN.md)；[契约提案](../architecture-addendum.zh-CN.md)。

## 目标

确认可稳定观察的事件，再在隔离 profile 证明最小接入，不把插件架构当完整接入证据。

## 范围与复用

- 研究固定 ce7073d51254c26cd63b22a60835b8f948deb447；执行时记录是否另选版本及差异，不追浮动 master 编写未经验证的事件名。
- 从官方架构的 typed events/session event 入手，列生命周期、工具失败、等待、会话标识、模型选择、重连/历史重放和卸载的确切来源与顺序。
- 研究阶段只交能力矩阵与小型合成输入；D0/A0 后做旁挂观察插件，使用独立 profile 与模拟 SS 接口。
- 只选择必要结构化字段，不订阅/保存消息正文流、工具输入输出或模型密钥；官方事件不等同 SS 交付。
- 验证重复挂载、断连恢复与插件卸载不残留监听；确认返回原会话/用量能力，不能验证就保留 unknown。

## 不做

不改上游 Agent 执行/权限决策逻辑，不装进用户默认 Harness，不修改公共 MCP 服务。

## 验收标准

1. 每种能力有版本、代码/文档依据、真实/模拟级别和未知项。
2. 相同原生 ID/切模型场景正确，插件自身失败不阻止 Agent 主流程。
3. 重复事件和重连历史不产生重复交付；卸载不留回调/连接/计时器。
4. 未启动付费模型会话、未改用户实际 profile；真实 Harness 使用单列待验。

## 验证

先静态官方资料核对；原型使用假事件源/假 SS，再另记真实工具验收。 每条标准写满足/不满足/无法验证；模拟 expected 不得填成真实已通过。

## 交付

研究报告、固定版本能力矩阵；依赖满足后才提交插件原型草稿 PR。 按共同六段格式回报，附精确候选、证据和未验证项；没有 PR 则明确仅设计/调研。用户确认与执行者自测分开。
