# M1：可纠正、带版本的项目记忆

状态：D0 后可先设计；实现依赖 D0/F0/P6，模型写入必须等 P6，迁移与公共负责人协调；本轮未实现。
分支建议：`feat/project-memory`。执行时从最新 main 创建独立 worktree；当前没有创建该分支。
共用约束：[索引与回报格式](README.zh-CN.md)；[契约提案](../architecture-addendum.zh-CN.md)。

## 目标

让用户看懂项目记住了什么，不再被 routine memories 摘要逐轮打扰。

## 范围与复用

- 定义项目隔离记录：目标、约束、用户决定、交付证据、卡点、下一步及负责人，带来源、时间、适用候选和修订链。
- 正文仅取 SS 已有结构化简报、交付与用户字段，逐字段白名单并保存来源引用；哪些是用户确认、程序核实、Agent 自述、模型提案分别标明。不得从 conversation、transcript、工具输入输出、通用 Agent 记忆或其他项目提取正文；引用不意味着可以顺带导入其隐藏全文。
- 拟议正文上限：单条 2,000 个 Unicode 字符，每项目当前有效正文合计 20,000 字符，模型提案同样受限；写入前校验，超限明确拒绝并让用户缩减，不静默截断后当完整事实。链接/证据 ID 不作为夹带正文或绕过上限的通道。上述为待实现参数，须在隔离测试中覆盖边界，不表示当前已有限制。
- 设计 proposed/confirmed/superseded/retracted 与纠错、过期及冲突显示；模型不能把提案静默改成用户决定。
- 用户界面按项目展示可读的新变化和证据，普通整理保持静默，只对具体待处理问题提示；保留 #39/#40 行为。
- 首期不默认同步记忆正文、不写入 ~/.codex/memories 或 Claude 内部记忆文件；SS 本身的项目记忆独立管理。

## 不做

不导入其他项目全文或通用 Agent 记忆，不拿模型摘要作为项目事实。

## 验收标准

1. 项目间不串记忆；同一交付更新不会重复记多条有效事实。
2. 过期版本、矛盾、撤回与纠错可查，原依据保留，不伪造历史确认。
3. 自动维护没有新增 routine 待办；有真实用户问题时只展示具体问题。
4. 模型建议的知道了/不对不会改变工作项或代码合并、安装、验证。
5. SS 简报/交付/用户字段之外的合成正文哨兵不进入记忆、日志、同步或模型输入；单条 2,000/2,001、项目 20,000/20,001 字符边界明确可查，超限拒绝不损坏已有记录。来源内容本身的事实等级保留，模型提案不能伪造用户确认。

## 验证

合成两个项目、多版本交付/纠错/冲突、来源白名单与长度边界，验证安静规则；界面沿用仓库 [WorkOverview](../../../../../web/src/ui/WorkOverview.tsx)、[RunDesk](../../../../../web/src/ui/RunDesk.tsx) 与 [town.css](../../../../../web/src/town/town.css) 的信息层级和样式，做前端测试/构建及实际预览截图，不依赖仓库外技能路径。每条标准写满足/不满足/无法验证；模拟 expected 不得填成真实已通过。

## 交付

项目记忆数据与交互设计、隔离实现候选及用户可读的示例记录。 按共同六段格式回报，附精确候选、证据和未验证项；没有 PR 则明确仅设计/调研。用户确认与执行者自测分开。
