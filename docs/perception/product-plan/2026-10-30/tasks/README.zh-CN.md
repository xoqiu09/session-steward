## P2 补充约束

以下是待实现的设计澄清，不能作为目前已具备能力的描述：

1. **批量核对和共享预算。** 优先设计 GraphQL 多仓库批量查询或 `gh search prs` 跨仓库搜索，不按 30 仓库逐个 REST 轮询。30 仓库每分钟一次、每轮可由单次完整查询覆盖时，基础约 60 次/小时；变化 PR 再追加 head/base/checks/merge 精确查询。分页、查询拆分、命令内部请求、失败重试都计入同一个每小时 300 次预算，不能把 gh 命令条数当 HTTP 请求数。记录请求账本、剩余额度、公平排队、上次成功核对和错误；超预算不偷偷绕过。
2. **一分钟目标等待用户 U04。** 保留原实时目标，由用户决定是否承诺一分钟、覆盖全部还是指定活跃/待合并工作、网络/权限/预算异常如何提示。需通过合成多仓库/分页与真实只读核查证明能力后再承诺；本轮不取消目标，也不代选范围。
3. **关联允许有证据的祖先。** PR head 等于本地分支当前 head，或已证明是其祖先时可关联；后者显示“PR 落后本地 N 个提交”，N 为可核对的 `PR_HEAD..LOCAL_HEAD` 提交数。检查结果始终绑定精确 PR head，不能转移给更新的本地候选。既非相同也非祖先、提交图不足或证据不明时不关联，不用分支名相似来猜。
4. **关联不放宽合并。** 合并确认仍核精确仓库/PR、当时 current head、base、merge commit 和目标分支包含证据，遵守原 squash 等证据规则。旧 PR 合并只更新其候选记录，不清除尚未合并的本地更新候选提醒，也不写用户已处理/功能符合要求/安装。

依赖表的 `depends` 表示完成实现的硬依赖；W2 用 `phases` 标出可先行逻辑阶段，F0 另列 `release_depends` / `release_gate`，不把发布顺序倒置为 U1 等 F0。机器检查同时校验实现与发布关系无环。PR42 作为外部 owner 单独登记，仅供 S22～S26 关联，不表示其已完成、已授权或是第 16 份任务书。

## 所有任务的共同执行边界

1. 执行前重新核对远程 main、HEAD、dirty、PR 状态和所需版本；主仓库的 assets 不暂存、不 reset、不 clean。需要写仓库时从最新 origin/main 建独立 worktree，既有 T0 例外仅用于原任务，不扩散为新任务例外。
2. 从本地工具包装器和已有缓存运行。只装任务明确需要并经项目授权的依赖；不全局安装工具或改正式账号/模型/代理配置。
3. 草稿 PR 使用中文标题和说明。已有推送分支不 rebase/force-push；不能把执行者自测写成独立审查通过。
4. 不合并、不发 tag/release、不签发生产密钥、不替换正式安装；不改多设备/Tailscale/同步密钥、其他工具设置。SS 对 GitHub 只读；开发 Agent 只有在本项明确获分配和授权时才开草稿 PR，写前核对账号 xoqiu09。
5. 用合成项目、事件、仓库和测试 home。真实工具测试只配置测试项目或隔离 profile；先核实工具是否真支持项目级隔离，不假设都有 STEWARD_HOME。
6. 模型自述/停止/动画不能写已处理或四类权威记录。hub 上其他设备和普通远端访问保持只读，remoteBlocked 原限制不变。观察桥接不提供暂停/发消息/批准；未来仅控制执行设备本机的入口按 D0 独立凭据、逐动作授权设计，审批默认关闭，用户 U06/U07 未决定不开放。
7. 写源码后按仓库 AGENTS 验证：Go 全仓测试，状态/并发加竞态；前端测试/构建和 dist。纯设计/调研不冒称已跑产品验证，也不为文档改动重跑全部产品测试。
8. 交付做 scoped worktree-lifecycle 检查，未合并/待用户检查的工作树保留，归档和备份不按缓存删除。

## 每项固定回报

结果／改动／验证／偏离任务书的地方／需要用户决定的事／PR。

明确写设计、模拟通过、真实工具通过、正式安装、用户确认分别到哪一步；每条验收标准记“满足／不满足／无法验证”，附候选、证据、截图和未验证项。没有 PR 就写“无，本轮仅设计或调研”。

合成总体验收矩阵见 [acceptance-plan.json](../acceptance-plan.json)，其中 expected 都是目标，不是已完成的测试结果。
