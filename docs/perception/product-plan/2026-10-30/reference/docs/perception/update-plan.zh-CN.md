### 已经做好的

| 部分 | 内容 |
| --- | --- |
| 用户操作 | 菜单“检查更新” → 看版本和说明 → 下载（有进度，可以重试） → “安装并重启” |
| 安全 | 清单用 Ed25519 签名，公钥在构建时固定写进 App；下载后核对大小和 SHA-256；解压时拒绝路径穿越、符号链接等；核对代码签名、芯片、版本、构建序号 |
| 替换 | 主 App，加上 `~/.steward/bin` 里的 `steward`、`steward-hook` 和通知助手，整组一起换 |
| 失败恢复 | 替换后健康检查不过，就恢复整组旧文件并重启；恢复本身失败的话，下次启动时提示“恢复旧版并重启” |
| 两种后台 | App 自管后台、共用 launchd 都支持；不会改 hooks 条目、配置、数据库、密钥和多设备角色 |
| 发布工具 | `steward-update-manifest` 离线签清单；CI 照旧只建草稿 Release，不碰私钥 |

### 还没做或有问题的

1. **和最新 main 有冲突**：这是 T0 任务书要做的事。
2. **数据库结构一变就拒绝升级**：清单里的 schema 版本必须和当前一致，否则提示“请手动迁移”。感知的每一期几乎都要加表或加字段（P1 就要加），所以照现在的规则，以后大部分版本都不能一键升级。这是最大的问题，见下面的 U1。
3. **没有生产密钥**：没有公钥的 App 会拒绝生产安装。密钥只能由你自己生成和保管。
4. **不会主动提醒**：第一版只在你点“检查更新”时才去查。
5. **第一次要手动装**：已经装了 v0.1.0 的人（包括你的两台电脑和朋友）手里的 App 没有升级功能，第一个带升级功能、带公钥的版本必须手动下载安装一次。
6. **未经 Apple 公证**：App 只有 ad-hoc 签名。新版本有可能被 Gatekeeper 拦下，那时升级助手会恢复旧版。要彻底解决，需要 Developer ID 签名和公证（Apple 开发者账号每年 99 美元）。

## U1：升级时迁移数据库

现在拒绝的原因是：失败恢复时要把旧程序跑回来，旧程序看不懂新结构的数据库。建议改成：

1. 停掉后台之前，用 SQLite 的在线备份把数据库完整复制到这次升级的事务目录，并记下备份时 `events` 表的最大序号。
2. 新版本启动时照常向前迁移。
3. 健康检查不过、需要回滚时：停掉新版本，把备份的数据库放回去，再用旧程序启动。
4. 备份之后新版本收到的事件（`events` 表里序号更大的那些），回滚后按统一事件格式交给旧版本重新导入，避免丢失。事件格式（`schema_version`）不兼容的，记在升级日志里，并在面板提示丢了多少条。
5. 发布清单里新增 `min_schema` 字段：只允许从这个版本以上的数据库升级，太旧的仍然要求手动处理。

这样，以后加表、加字段都可以一键升级；回滚也不会让数据库停在旧程序打不开的状态。

## 已决定（用户 2026-10-29 确认）

1. **第一个正式版本号是 `v0.2.0`**。等 U0～U2 和感知 P1 一起合并以后再发，这样朋友手动装一次，就能同时拿到升级功能和第一批感知改进。
2. **做 U1**（升级时迁移数据库）。
3. **暂不申请 Apple 开发者账号**。只有两台电脑和一两个朋友在用时，ad-hoc 签名够用；准备给更多人用时再申请。
