# 共用契约草案：身份、来源、能力、操作与记忆

状态：`ss-perception-extension/2026-10-30-draft2`，**设计提案，尚未实现，未冻结公共 API**。本轮仅按 PR #41 审查修订文档，不启动适配器或控制实现。
前置：原 [感知架构](reference/docs/perception/architecture.zh-CN.md)、现有 P1/P3 和用户本次设计 context。D0 负责审查并产出冻结版本；A0 负责公共实现。

## 1. 三层与写入边界

- 感知与核对复用现有 Ingest：去重、乱序、绑定区间、工作项/会话/运行/审批分离。原生停止或子待办完成只是观察。
- 小镇只消费快照和已核实变化。动画、常驻、视角、看过动态等偏好不改变工作状态。
- 小猫通过独立解释接口写建议。其文本、反馈或项目记忆提案都不能写用户处理、代码合并、设备安装、运行验证记录。

## 2. 会话身份：保留旧语义，模型不进主键

现有数据库已经使用 `(host_id, provider, provider_session_id)` 唯一约束。不要把它描述成没有跨设备/工具隔离，也不要把 `provider` 直接改成模型厂商。

| 语义 | 草案字段 | 兼容和来源 |
| --- | --- | --- |
| 设备 | `host_id` / 对外 `device_id` | 服务端从本机安装身份或已认证设备得出，不接受桥接调用随意冒充远端设备。 |
| 执行工具 | 现有 `provider`；`execution_tool` 仅为文档语义名 | 新增值使用工具 ID，如 `deepseek_harness`、`workbuddy`、`codebuddy_cli`；旧 `claude/codex/other` 保持原值。不新增第二列、不改唯一键，也不批量迁移旧值。未知新工具不能统一折叠成 other。 |
| 客户端入口 | 原 `client`、版本、适配器版本 | CLI/桌面入口不应在原生会话本就相同的情况下制造重复会话。 |
| 原生会话 | `native_session_id` | 对应旧 provider_session_id；没有原生 ID 时由已认证桥接上下文分配独立本机会话，显示“桥接会话”，不猜别的工具的会话。 |
| 运行 | 内部 run ID、可选 `native_run_id` | 由明确开始/交接建立关联；原生 turn ID 不直接当成 SS 工作完成。 |
| 模型 | 拟议 `model.provider`、`model.name`、`observed_at`、`source` | 新增记录须先获用户 U03 授权；未获准不新增采集/持久化。可未知；获准后按运行/时点追加观察，换模型不换会话，不读密钥或根据自定义地址猜厂商。 |

规范会话键仍对应“设备＋执行工具＋原生 ID”。原生 ID 复用/会话代际需有工具证据才能另开 incarnation；不以收到时间随意制造新会话。数据库重建、工具重装的映射由 A0 明确处理并测试。

兼容现有 `ResolveSession` 的两处 other 分支：在 main `internal/core/ingest.go:389` 的按原生 ID 查询中，空值/other 会跳过 provider 条件；在 `:415` 的目录候选选择中，空值/other 会匹配任意 provider。旧路径保留兼容，新适配器必须从认证工具上下文传入非空、明确的 `workbuddy` 或 `deepseek_harness`，因此走精确 provider 过滤/匹配；不得借 other 猜到另一个工具，多个候选仍报冲突。D0/A0 须分别覆盖两处分支及旧 other 兼容，不把仅改文档名当成隔离已验证。

项目定位使用稳定的来源设备＋来源项目身份。hub 的偏移数字 ID 和设备显示名只用于显示/路由，不作为永久地图坐标键；也不按仓库 URL 或项目名自动合并不同设备项目。旧摘要缺少稳定身份时保留兼容映射，不能重排整个世界。

## 3. 信号渠道、可信等级和时间

保留 P1 的渠道集合：`hook/transcript/process/git/github/hub/model/user`。**不额外把 MCP 混成一个并列事实来源。** MCP 是传输方式，其任务回报仍是 Agent 回报；建议增量元信息如下，由 D0 核定字段名：

```json
{
  "contract_status": "proposed",
  "provider": "claude",
  "model": {"provider": "deepseek", "name": null},
  "provenance": {
    "channel": "hook",
    "transport": "mcp",
    "origin": "agent_report",
    "occurred_at": "2026-10-30T08:00:00Z",
    "received_at": "2026-10-30T08:00:01Z",
    "time_basis": "client_reported",
    "evidence_id": "synthetic-evidence-1"
  }
}
```

这个片段是契约说明，不是当前服务器可以直接接收的 Event；其中模型字段也受 U03 门槛约束。现有字段须由适配层映射；客户端不能自行把 `origin` 升为 `program_verification`。

渠道写入白名单由服务端校验：`/hook/*` 只允许 `hook/transcript/process`（空值按既有规则归为 hook）；`user` 只由已认证用户操作（现有 panelTx）产生；`git/github` 只由对应核实器产生。hook 自报 user/git/github 必须拒绝且不能刷新 LastSignal、LastSignalAt；MCP 也不能借 channel 获得核实器身份。F0 的整合范围和验收必须同时包含此规则。

`origin` 语义候选：`automatic_observation`、`agent_report`、`program_verification`、`user_action`、`model_interpretation`。模型解释只能走 P6；核实事实的写入者由服务端权限决定，不能靠传入枚举获得权限。

每个信号记录来源、设备、发生时间、收到时间和回查依据。缺原始发生时间时明确标适配器处理时间，不编造精度；过度未来时间、时钟漂移、重连旧记录不得锁死后续状态。沿用 P1 的事件时刻排序和优先级，跨任务归属按当时绑定区间核对。

来源内幂等键优先用“认证设备＋工具＋原生事件 ID”。有 tool_use_id 的跨渠道重复沿用“会话＋调用 ID＋事件种类”规则。没有稳定原生 ID 时，由适配器持久化本地递增记录标识，不以每次重连生成新 UUID 掩盖重复；不以模糊文本相似度删除事件。

## 4. 能力与连接健康分开

每个能力各自声明以下状态：`verified / unverified / unsupported / unknown`。验证必须绑定工具版本、适配器版本、平台、场景、时间和证据；模拟通过不等于真实工具已验证。文档没写通常只能记 unknown，不能直接记 unsupported。

首期观察能力：生命周期观察、等待输入观察、工具失败观察、主动 begin/report/deliver、用量、返回原会话。后续本机控制能力逐项列为 start/input/interrupt/stop/resume/approve；能力表另将“恢复原生会话”和“官方 App 接手”各列一行并分别给版本与证据，不能用一个“可控制”代替。**“看到等待批准”不等于“可以代替用户批准”。**

连接健康另记 `online/offline/stale/error/unknown`、上次接收及原因。连接在线不能让未知能力变成 verified；掉线也不能把工具会话自动判成已结束或任务失败。

## 5. 操作入口

由服务端提供受控动作描述，界面根据动作 ID 调用现有路由；不渲染模型给出的 shell 命令或任意 URL。动作包括查看交付、去原会话、查看证据、重新核对、管理状态。

- 已有 Codex/Claude 返回入口复用；返回成功要由真实对应会话验证，不能仅凭应用被唤起。
- 不支持指定会话时显示限制及经核实的替代入口；未知时禁用并说明，不假装已支持。
- hub 上其他设备的工作继续只读，返回提示去来源设备；第 6 节只设计控制执行设备本身，不借 hub 向其他设备转发控制。
- 常规工作闭环显示“已处理”，功能是否符合要求是独立确认；模型解释的“知道了”不触发任一工作完成记录。

## 6. 仅控制执行设备的本机控制提案

这一节为新增设计，**没有实现、没有开放手机访问、没有验收 PR #42**。是否启用及允许哪些手机动作须用户 U06 另行决定。本轮执行设备只指 Mac Studio 本机；它兼任 hub 不等于获得控制其他设备的权限。PR #42 是待逐项审查的外部原型输入，不是另一套业务状态来源。

- **认证与动作隔离。** 未来本机控制入口须用独立、按设备签发且可撤销的凭据，逐项授权 start/input/interrupt/stop/resume/approve，并绑定允许的项目/会话。approve 默认关闭，只有用户 U06 另行明确允许才能实施/测试开放。不能复用 `remote.token`、只读 cookie、面板 token、hub/同步密钥；观察 MCP 的 begin/report/deliver 权限也不自动取得控制权。
- **维持现有拒绝边界。** 普通远端访问仍受 `remoteBlocked` 原规则约束：`/api/managed*` 和 conversation 即使 GET 也拒绝，其余写方法仍拒绝。若未来增加本机控制 path/listener/router，须独立认证和逐动作鉴权；用普通远端只读 cookie 调它一律 403，不能为了手机复用而放宽现有远端路由。真实监听、手机连接路径与网络变更待用户 U07 决定，本轮不修改。
- **唯一控制登记。** 未来优先复用 LaunchManaged，将 WorkItem 与托管会话同事务登记，把生命周期、幂等启动、输入所有权与审计整合到现有 `managed_sessions` / `managed_audit` / `ReconcileManaged`，复用 WorkItem/Session/Run 关联；不创建第二套 task/control 状态机。PR #42 的原型数据须逐项映射或收敛，不能直接并存两份“当前状态”。每个控制动作审计设备、动作、时间和结果，仅记类型/长度，不写命令或输入正文，也不把恢复命令塞入摘要。D0 定契约，A0 负责未来公共实现，I0 按精确原型候选验收。
- **恢复与 App 接手分开。** 原生 Session ID 只从 Codex hook 或会话记录取得，不从启动命令推测。本机原生 CLI 恢复须指定该 ID（如 `codex resume <SESSION_ID>`），并核对同一会话历史；禁止 `--last` 猜测。官方桌面 App 接手是独立能力，须证明同一 Session ID 与历史连续。只打开 App、带摘要新开聊天或无法核对 ID 均不能标已接手。App 未验证时是否接受仅 CLI 恢复由用户 U06 决定。
- **并发与失败默认收紧。** 断连重连保持同一托管/原生会话，后台 reconcile 不因手机离线停止；重复 start 使用幂等键与同事务业务/审计关联；手机与电脑输入只能一方持有有效 lease/epoch，接手须撤销旧所有权并审计。发现直接终端恢复且无法证明所有权时禁用手机输入并显示 unknown，不向两个入口同时注入文字。
- **批准与重启。** 审批默认关闭时，手机/只读凭据请求拒绝；只有用户日后明确授权审批后，才验指纹、过期与重复竞争，电脑已批准后手机旧请求应返回冲突而不重复改变状态。执行设备重启后没有进程/tmux 的记录应 reconciled 为 exited 并给原因，不自动重开任务；用户选择恢复，仍分别验证原生恢复/App 接手。

S22～S26 的 owner 为“PR42 外部原型候选＋I0”，全部 `not_run`。已存在的 main 托管机制是复用依据，不表示这些新增约束已经在原型或正式版成立。

Ekko 研究须先固定仓库 URL、commit、许可证文本/文件与署名要求，并产出逐文件复用清单；在用户 U08 决定前不复制代码、不推断未知许可，不把与主项目许可证不兼容的内容带入主线。隔离个人试验也不能代替许可核验；无法核实时只研究公开设计思路并保留未知。

## 7. 公共观察桥接与认证

A0 维护唯一公共桥接实现，A1/A2 只实现工具适配。优先本机 stdio MCP 或受控 CLI；如需本机 HTTP，仅回环并单独认证，不能直接复用中心机同步密钥或全权限面板令牌。

桥接授权限制设备、工具、项目及动作。初期仅允许登记、回报、交付和必要事实读取；拒绝用户处理/批准、归档删除、合并、安装验证以及伪装其他设备/工具。传入的工作项 ID 必须与授权项目一致。卸载/停用应撤销桥接权限及自身配置，不清除业务历史。

上述是观察/主动回报桥接的限制；第 6 节本机控制是另一个待授权设计入口，不由这里的观察凭据启用。两者复用同一业务与托管登记，不复制状态机。

模型密钥继续归执行工具管理。MCP 位于本机不代表执行工具使用的模型一定在本机；给它的事实默认只包含该项目必要摘要。小猫解释继续使用获准的本地模型，不自动切到远端供应方。

## 8. 世界位置与动态恢复

W1 把稳定坐标、常驻偏好与动态状态分离：状态只改徽章、人物和光效，不每天换地块。首次分配沿用现有世界布局，后续增量分配；归档留下可恢复关系，恢复优先回原位。常驻项目仍能归档，不自动恢复已归档项目。

视角按设备/视图范围保存；切回同一范围恢复视角，不以每次快照重新适配全景。世界首次展示整体范围，显式“全景”仍可重置。宽屏仅有本机几项工作时也用世界视图，窄屏继续现有分页，不能用虚构项目填充真实项目数量。

W2 复用 V1 队列和 3 秒窗口。持久看过标记与数据源/设备范围、快照代际隔离；刷新、SSE 重连、设备短暂离线和程序重启只补“离开期间”摘要，不重飞旧交付。离开摘要不是新交付事件。用真实变化依据排序，保留减少动画、30 秒静默和返回位置行为。

## 9. P6 解释与 M1 项目记忆

P6 事实接口复用快照，解释包含项目/工作项、类型、文本、模型、生成时间、依据标识、依据版本和过期状态。事实更新后旧解释可保留但标过期；缓存按依据版本，不定时对全世界重复问模型。重要变化或用户请求触发，失败有程序式信息缺口提示。

本机依据可用受控 evidence_id 回查。远端摘要沿用只发送渠道和时间、不发送私有 Ref 的规则；小猫引用远端只能指向允许的快照/工作项/信号时刻，并明确“依据设备摘要”。不能为了点击回查而把路径、对话、命令或恢复命令塞进 hub 摘要。

M1 是 SS 的项目记忆，不是抓取 Codex/Claude 的通用记忆目录。记录目标、约束、用户决定、交付/证据、当前卡点与下一步，带项目 ID、来源、时间、适用候选、状态和修订链。候选状态为 proposed/confirmed/superseded/retracted；哪些可由程序确认、哪些只能由用户确认，由 M1 逐项定义。

首期正文输入仅限 SS 已有的结构化简报、交付和用户字段，不从 conversation、transcript、工具输入输出或通用记忆文件提取正文。拟议上限为每条记忆正文 2,000 个 Unicode 字符、每项目当前有效正文合计 20,000 字符；超限明确拒绝并让用户缩减，不静默另抓全文或把截断文本当完整事实。引用只带允许的 evidence_id/版本，不借引用导入隐藏正文；模型提案同样受来源与长度限制，细则见 M1。

普通整理、压缩和记忆同步保持安静；用户只看到“这个项目新记住了什么、依据是什么、是否过期”，能纠正。模型提议不静默变成用户决定；已合并不静默变成已处理；不得重新产生 memories 摘要类逐轮待办。记忆正文跨设备同步不在本次默认范围，需先确定字段白名单。
