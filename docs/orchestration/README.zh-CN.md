# SS 本机编排开发候选

先读 [共用契约](contract.zh-CN.md)。本轮从 OR-C0 开始，增加本机 Router、持久事件收件箱和只读 Watchdog 的首版实现。代码仍沿用 WorkItem、managed_sessions、原生 thread/turn、已有审批和用户验收。默认停用，不自动改正式配置或启动任务。

## 如何使用

1. 在派活台将本机项目加入“可派活的项目”。在原工作项填写目标和验收条件。
2. 在“把后续交给后台推进”中选择工作项、输入本次允许做的事情，设置回合与到期边界，并明确允许短期保存输入。可选择是否允许同一可核实候选的工具失败观察返回原负责人。
3. “只观察”不执行。“按授权推进”仍只允许已授权工作；你正在控制派活台时，必须明确点“交回后台”才会自动送入新要求。后台期间随时可以“接过来”，页面关闭不自动归还控制。
4. 当前轮正忙就排队；原生工具接纳后显示“Codex 已接纳”，不代表工作完成。正文在接纳或取消后清空，未消费最长保存一天，逻辑删除不承诺清除 WAL/备份的物理痕迹。
5. 结果不明时停止自动重送。先核对原会话，可核对已记录回执或明确结束该输入且不重发。若原生会话仍待核对，需要在原派活任务中明确恢复/核对，不能用重新授权绕过不确定执行。
6. 原负责人可在新建会话使用 `ss_return_event` 退回无关、范围不清或依据不足的投递。退回后保留原事件与原因，等待重新确定归属，不循环派回同一人。旧会话能否使用新工具单独记为未验证。

输入超长、包含已识别凭据、没有暂存许可、任务关闭或未明确退回修改、项目未允许、目标/目录/分支变化、授权到期、身份不匹配都会拒绝或暂停执行。审批继续在原有本机卡片明确处理，后台不会替你允许。

## 首版边界

先采用一项工作一名 Codex Worker，全局最多两个活跃 Worker、每项目一个；支持沿用唯一的现有原生托管任务。没有可靠执行身份的已有会话阻止自动重复派活。旧 Claude/tmux 或其他非原生派活工作的续接需要明确交接；不会因为它空闲就自动从 main 重开。工作项、项目、来源、授权版本与负责人代次均参与核对。

失败直通和重复失败检查只使用能核实仍相同的干净提交候选。脏工作区、旧候选和来源缺失不能被当成新候选失败。Watchdog 只读取限定记录并提供依据，不调用模型、不自动停止/重启，也不会把长命令、审批或信息不足叫作卡死。当前模型语义跑偏解释、真实 CI 订阅和其他执行工具没有被接通。

追加迁移版本为 7；升级采用现有串行事务迁移。迁移失败不前进版本；回到旧二进制需要恢复升级前备份，不允许旧版直接写新 schema。本轮没有替换正式安装或迁移真实运行库。

## 隔离合成预览

预览使用真正的 SS HTTP、SQLite、Core 和原生适配器，最后一层替换为合成 RPC，不启动 Codex、不调用模型、不修改 hooks、不采集历史会话。数据和 worktree 都来自演示目录中新建的空 Git 仓库。

```sh
go run ./scripts/orchestration-preview /Volumes/LocalDevData/Codex/Scratch/ss-orchestration-preview
```

程序打印本机登录 URL，监听随机回环端口。合成执行器每轮约五秒后报告回合结束，不假装交付或验收。按 Ctrl+C 停止；演示目录是独立资料，真实数据不应放进去。

## 验证与交付

产品自动验证按仓库 AGENTS 执行 Go 全量、竞态和前端测试/构建。测试使用假执行器、假时钟和合成 Git 仓库，覆盖授权版本、接手、幂等、队列、候选变化、重启结果不明及隔离权限。准确运行结果和剩余场景以本轮任务目录的交付回执为准，不因存在测试代码就记为通过。

真实 Codex、真实 CI、正式安装和用户使用评价均独立记录；合成预览不是用户验收。没有对图中的外部合成负载数字作性能承诺。
