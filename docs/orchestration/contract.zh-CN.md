# SS 本机编排共用契约

版本：`ss-orchestration/v1`。基线：`90af7946140c97d79fd20391da5d940e72d216bf`。本契约是 OR-C0 在本轮开发采用的内部边界，不是公共桥接 API，也不表示用户已经验收实现。

## 业务对象与兼容映射

| 概念 | 既有来源 | 本轮增量 |
| --- | --- | --- |
| 工作 | work_items，title、acceptance、status，brief_entries.goal | 不增加 Task；授权保存这些字段的版本摘要，目标变化要求重新授权。 |
| 执行归属 | managed_sessions、Session、Run | Assignment 只引用原工作项与托管记录；一个工作项一份有效归属。设备/工具/原生 ID 三元组不变，不用模型作为身份。 |
| 依赖 | work_deps.accepted/merged | 依赖未满足就等待；自动调度不能写用户验收放行。 |
| 权限 | Approval、指纹、handleable、原生审批 | 只复用，后台没有允许/拒绝工具审批的能力。 |
| 交付和验收 | deliver、review、用户处理、功能候选验收 | 接纳输入、结束回合、检查恢复均不改变验收。done/abandoned 不自动重开。 |
| 来源 | events、发生/收到时间、绑定区间、P1 来源白名单 | 订阅游标从授权当时生效；旧事件不新建任务，不按名称猜归属。 |
| 控制 | Desk 面板租约和原生 thread/turn | 后台使用专门内部身份，与用户控制互斥；不模拟 client/epoch。用户接手后须明确交回后台。 |
| 恢复 | ReconcileManaged、native needs_reconcile/uncertain | 结果不明不重发。输入接纳与消费分开，不承诺任意 shell exactly-once。 |
| 展示 | 派活台、工作项、Notifier | 编排是附加信息，不修改原快照的业务含义，普通远端与 hub 仍只读。 |

## 权限矩阵

| 写入者 | 可以 | 不能 |
| --- | --- | --- |
| 认证的本机面板用户 | 为允许项目的现有工作项授予/撤销有限授权，启停模式，明确追加要求，接管与交回控制 | 本轮不新增远程写入、任意 shell/目录/模型配置入口。 |
| hooks 与普通 Agent | 原有 begin/report/deliver 和受限观察 | 授权、模式、归属、用户处理、功能验收和编排控制。next_owner 只是回报。 |
| Router | 校验授权、依赖、名额，登记决定和归属，调用已允许的内部执行入口 | 自行授权、批准工具、重开已完成工作、合并/发布/部署或取得其他设备权限。 |
| 事件投递器 | 对唯一归属建立投递，在安全边界发送，保存接纳回执 | 将评论/日志的指令当系统规则、扩大范围、忙时敲终端、盲重发未知请求。 |
| Watchdog | 读限定事实，写发现、依据、确认与恢复记录，提出建议 | 执行、停止、重启、审批、扩大预算、改事实或用户验收。 |
| 可选模型 | 有授权时解释限定事实 | 创建授权、提升来源可信度、把推断写成程序核实。目前不新增模型调用。 |

## 授权及模式

默认 disabled，observe 只评估、无执行副作用；enabled 仍逐工作项校验。授权仅来自认证本机用户，不是客户端可自报的角色字段。授权绑定项目、工作项、目标摘要、版本、有效期、最大回合数及是否允许失败观察触发后续；首版不授予自动拆解或自动转交其他执行者。

仅接受已经加入 dispatch_projects 的本机 Git 项目；执行目录由服务生成，不能由请求选择。首版一个目标对应一个现有工作项、一名 Codex Worker；已有不受本系统控制的活跃会话阻止自动派出第二名。现有 LaunchDispatch 会新建工作项，因此后台复用内部 launchOpts.item 的语义，不能重复 Desk.Create。已有非原生托管会话的历史工作或不同分支必须先明确交接，不能因为旧会话空闲就从 main 重开并丢掉上下文。首版不自动承诺 Claude/tmux 到原生 Codex 的跨工具交接。

建议默认：全局 2 个活跃 Worker、每项目 1 个、每工作项 1 个；每次授权最多 10 回合、最长 4 小时，可在边界内由用户缩小/调整。金额与 Token 用量未提供可靠探针时显示 unknown，不承诺硬费用上限。到期限制新的回合接纳，不强制中断已接纳回合；停止仍由用户决定。传输已证明未执行时最多额外重试 2 次；权限拒绝、任务失败和结果不明不属于传输重试。

撤权、到期、目标变化、移除项目、暂停/委托、工作关闭、用户接手均阻止新动作。已经接纳的动作保留事实，不声称撤权能撤回既有副作用；尚在连接阶段的请求在 turn/start 前再次检查。

## 能力表

| 能力 | 当前源码 | 首版使用边界 |
| --- | --- | --- |
| start | K1 已有 thread/start、turn/start | 在新 worktree 中启动，复用 WorkItem，不改变原项目。 |
| resume | K1 已有按明确 thread ID 恢复 | unknown/needs_reconcile 不自动恢复执行，由本机用户核对。 |
| input at boundary | K1 空闲时可开始下一轮 | 收件箱持久等待回合结束，再查权限/归属。 |
| steer | K1 正忙拒绝 start | unsupported，首版不调用未验证 API。 |
| interrupt | 面板已有 | 仅本机用户；Watchdog 不调用。 |
| approval | 原生请求映射 Approval | 仅现有本机明确用户决定；后台不能允许/拒绝。 |
| delivery acknowledgement | turn/start 返回精确 turn ID | 只代表原生接纳，不声称模型读懂或执行完成。 |
| model interpretation、真实 CI | 尚未接入本阶段 | unknown/未验证；模拟与真实能力分开。 |

工具版本、平台与真实验证记录独立于上述源码能力，不能因为连接在线就标真实通过。补充输入结果不明时，可由本机用户核对已记录的精确原生回执，或明确结束该输入且不重发；结束核对不声称副作用未发生。

## 持久队列与幂等

订阅作用于单工作项、授权版本及当前归属；首次游标是授权时 events.seq。初始工作请求、明确用户反馈、本工作项的失败观察使用稳定事件 ID。普通 UserPromptSubmit、提醒回执或 Agent 自述不产生自动后续。真实 CI 来源另验，旧候选观察不转给新候选。失败直通只使用原生执行适配器记录且仍匹配当前干净提交的 candidate；工作区有未提交修改或无法核实候选时不自动按失败启动后续回合。

投递区分 queued、waiting_boundary、sending、acknowledged、retry_wait、held、uncertain、cancelled。逻辑 ID 由工作项和来源事件确定，同 ID 不得换正文或版本后重用。新建原生会话提供 ss_return_event 工具，按当前 managed/工作项/代次/精确回合核对后，将无关、缺少范围或依据的输入退回路由审阅；不再自动派回同一负责人。既有旧会话的该工具能力不作已验证承诺。至少一次传输配合稳定 operation ID；发送前记录 sending，重启遗留 sending 标 uncertain，不能不加核对地重发。

同工作项待处理上限 100 条，每条输入上限 4096 个 Unicode 字符；超过容量明确拒绝并保留来源游标，不丢掉未处理来源。仅用户明确允许保存的任务输入可以排队，脱敏后存储，拒绝包含已识别凭据的输入；接纳/取消即清空正文，未消费最长保存 24 小时，到期 held 并清空，不能悄悄执行截短内容。元数据和审计不保存命令、日志或对话全文。清空正文指可查询字段的逻辑清除，SQLite WAL 与备份不承诺物理安全擦除。运行数据库及目录继续遵循现有本机私有权限，不同步给 hub。

当前 launch 在业务事务前建 worktree。后台先事务内预留稳定 managed ID、分支、base SHA 和归属，再做可核对的目录准备与托管登记；崩溃恢复只承认本操作的已登记路径/分支和基线，不删除不明或脏目录。磁盘准备或执行是否成功未知时转核对，不以本地无回执推断没有执行。

## 检查与通知

Watchdog 每 60 秒至多做一次到期检查；无模型轮询。可运行无人推进 2 分钟、同候选 10 分钟 3 次同类失败、确认执行中 15 分钟无可核查进展是提示阈值。长操作、审批、外部等待、排队、缺探针和陈旧数据必须抑制或标信息不足，不以沉默证明卡死。核心功能矛盾仅按同候选依据解释。

发现保存依据版本与时间，区分事实、Agent 回报和推断。相同问题未变只通知一次，知道了不表示解决；有新恢复事实才关闭，重发有独立一轮记录。Watchdog 不自动重试工作，所有执行预算只有 Router 一处计数。

## 契约审查样例

C01：同原生 ID 分别来自两设备/两工具，保留四个身份；两个 WorkItem 不因标题相同而合并。Assignment 只能引用原对象。

C02：PR 文字要求批准、hook 自称 user、模型要求增加目录，均无授权效力；认证本机用户在版本 v1 授权后，v2 撤销阻止旧队列。

C03：在线但 steer 未验证仍排队；observe 不启动；面板接手后旧后台请求失效；页面关闭不自动交回。

C04：迁移仅追加编排附属表，旧配置不启用；既有状态/主键/审批/hub 接口不改义；迁移事务失败不前进 schema，旧二进制回退须用升级前备份，不直接打开新 schema。

上述为本轮契约样例与自审，不等于独立审查或用户验收。运行断言在 OR-R1/OR-E1/OR-W1 与 OR-I1 验证。
