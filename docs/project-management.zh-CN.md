# 项目管理、回收站与外部合并核对

## 自己选择归档或删除项目

在完整面板和桌面小镇顶部打开“项目管理”，也可以直接点“已归档 N”或“回收站 N”。三个分类只列这台电脑的项目，并显示各自数量：

- **使用中**：正常显示在小镇、项目简报和每日十分钟。勾选后可批量归档或删除，每行右侧也有单独入口。
- **已归档**：暂时不用的项目。在这里可以恢复到使用中，也可以移入回收站。
- **回收站**：已删除的项目。恢复会回到删除前的分类，原来已归档的项目仍回到已归档。

搜索支持项目名和目录，同名项目显示完整目录以便区分。“全选”只作用于当前分类、当前搜索结果；更换分类或搜索会清除选择。操作前会列出本次项目及目录；存在待批准请求或状态显示运行中的会话时会额外提示。确认期间冻结本次清单，取消不会修改任何项目。

归档和移入回收站都会从当前小镇、日常待办、菜单栏计数、通知和多设备摘要中收起项目。它们保留代码目录、Git 分支、工作项状态、验收记录、会话和用量历史，不会停止执行，也不代表验收通过。新的 hooks 不会自动恢复项目。

这里的“删除”是可恢复的移入回收站，不会删除本地代码目录，也没有清空回收站或按天数永久清理的功能。历史 API 的记录始终保留。两个分类的偏好存放在原有元数据中，不增加数据库版本；恢复、重复操作和项目路径别名合并都保留原分类。

每台电脑管理本机项目。操作后本机立即刷新；其他设备在下一份摘要到达后同步地图。这是显示状态同步，代码文件不随之移动；当前不会从中心机替其他电脑批量归档。远程浏览面板继续只读。

本机接口沿用面板认证和修改请求校验：`POST /api/projects/archive` 接收 `ids` 与 `archived`，`POST /api/projects/trash` 接收 `ids` 与 `trashed`。每批 1 至 200 项，原子写入；回收站项目需要先通过回收站恢复，不能用普通归档恢复绕过原分类。

## 在别处合并以后

有待合并工作项的项目每分钟核对一次远端；“项目管理”底部展开“外部合并核对”后的“立即核对外部合并”可以手动触发。核对只读取远端到专用 Git 引用，不切换分支、不拉入工作目录、不创建合并，也不推送。

小镇确认当前源提交已被本地或远端目标分支包含后，会将工作项标为“已合并”，关闭对应旧合并请求，并记录源提交、目标提交、核对时间和来源。本地已有的远端跟踪记录也能提供证据，界面会区别于刚读取的远端。工作项原来的待验收状态保持不变；外部合并不会被补写成人工批准。

GitHub 的 squash/rebase 合并另外通过本机已安装、已登录的 GitHub CLI 查询合并记录。必须同时匹配当前源提交、源分支和目标分支，并且合并提交已包含在取回的目标分支中。只匹配分支名、Agent 自述或 PR 已关闭都不能证明合并。

网络、Git 访问权限、GitHub CLI 或账号不可用时，管理界面显示核对结果和限制，未确认的工作保留原状态。其他托管平台的 squash/rebase 合并目前需要人工另行核对。归档的项目暂停周期合并核对。

这项同步只核对 Git 合并事实。原聊天中的普通决定和工具权限仍遵循各自的审批通道。

## 自己管理工作项状态

在“每日十分钟”的卡住、待验收、交给你处理的卡片旁点“管理状态”；工作项详情顶部也有同一个入口。选好处理方式、写可选说明后，点明确的确认按钮保存。

- **标记已验收**：由你确认工作项已完成，退出卡住和待验收列表。保留旧简报和操作记录；代码合并、核心功能的验收独立记录。
- **记录已转交**：填写接手人或接手会话，收起日常催办。只保存交接记录；不会发送消息或启动新会话。
- **暂停提醒**：保留工作进度，收起日常催办，不停止运行中的会话。
- **继续处理**：恢复执行中及日常跟进，把旧卡点归入历史。新的 Agent 回报仍可报告新问题。

已转交和暂停的工作在页面下方“已转交或暂停提醒”中，可展开管理或恢复。人工选择不会被后续 Agent 回报静默覆盖；正式权限、问题和合并请求仍遵循原有通道。操作记录以用户来源写入简报历史，不伪装成 Agent 进展，不自动验收其他工作。

合并管理中的旧错误在没有待核对工作时不再显示为当前故障。原项目目录失效时显示历史说明；恢复目录后会重试。GitHub 默认账号无权读取某个已配置仓库时，可尝试本机已登录的其他账号，并仅记住该仓库成功的账号名称。密钥只在查询子进程内使用，不写入 Git 配置、项目文件或全局登录状态。

## 看懂右侧工作详情

从左侧打开工作后，右侧默认先显示目标、最近进展和现在需要你做什么。进展带来源；没有回报时保留缺失说明，不据会话活动推断完成。

“已完成”与“代码合并待批准”可以同时存在：前者是工作项状态，后者是单独的代码合并请求。权限、问题和合并请求现在都能在当前详情里处理，不再让你回到被详情挡住的右侧队列。一次合并涉及多个工作项时仍显示全部成员；候选失效或资料不完整时不能批准。

提交编号、会话层级、运行版本、时间线和命令默认折叠在“执行记录”。功能验收、完整简报、用量与交接在“更多资料与管理”。日常先看摘要与待处理事项，需要核对来源或排查执行过程时再展开。


## 画布阅读与定位

画布按窗口宽度排列项目分区，同一项目内部保留任务依赖方向。独立任务使用紧凑网格，空项目或已收起项目只保留标题区域。默认使用可读比例，状态更新不会自动把整张图缩进一屏。

- **跳转到项目**：定位对应项目，并恢复阅读比例。
- **适合阅读**：恢复当前项目的可读视图。
- **全景**：查看项目整体分布；比例较小时会提示返回阅读模式。
- **定位选中**：回到当前工作卡片；打开详情引起窗口变窄时，也会定位选中任务。
- 点击项目标题展开或收起，点击任务卡片查看完整详情；可开关依赖连线，或通过底部按钮缩放。

画布只改变展示和导航，不改变项目归档、任务状态或用户验收记录。
